# No Azure SQL Database, a API entra com usuário contido e o login do MCP não existe

Os scripts de `database/` são a fonte única do schema (ADR 0003) e rodam sem mudança no SQL Server do compose e no Azure SQL Database do deploy (ADR 0007). No Azure, o `USE` não troca de banco e o banco da aplicação não cria login no `master`. Por isso, quando `SERVERPROPERTY('EngineEdition') = 5`, `02-criar-login-api.sql` cria `joya_api` como usuário contido (`CREATE USER ... WITH PASSWORD`), com os mesmos papéis `db_datareader` e `db_datawriter`. No SQL Server, continua o par login + usuário. O DDL de cada motor fica em `EXEC`, porque o Azure recusa `CREATE LOGIN` até num ramo que não executa. O `05-criar-login-mcp.sql` não cria nada no Azure: o MCP só lê o banco local (ADR 0010), e um usuário a mais no banco público seria só mais uma senha para vazar. Os testes de integração rodam o ramo do SQL Server. O ramo do Azure é verificado ao aplicar os scripts no deploy (`scripts/wizard-deploy.sh`).
