# Atrás da Vercel, o rate limit conta pelo IP de saída da Vercel

No deploy (ADR 0007), a requisição passa por dois proxies: a Vercel repassa `/api` para o Render (ADR 0011), e o proxy do Render acrescenta ao `X-Forwarded-For` o IP de quem conectou, que é a Vercel. A API mantém `ForwardLimit = 1` e confia só na rede interna do Render (`ProxiesConfiaveis__0 = 10.0.0.0/8`, no `render.yaml`). Por isso ela enxerga o IP de saída da Vercel, e os visitantes que saem pelo mesmo IP dividem o balde de 100 requisições por minuto. Confiar em mais um salto daria o IP real, mas a URL do Render é pública: quem a chamasse direto escreveria o IP que quisesse no header e escaparia do limite. Os IPs de saída da Vercel não são publicados, então não há como confiar só neles. Escolhemos falhar fechado: para uma demonstração com pouco tráfego, o balde compartilhado custa pouco. Se o tráfego crescer, a saída é provar a origem com um segredo (um header que só a Vercel envia, por um middleware dela) antes de confiar no segundo salto.
